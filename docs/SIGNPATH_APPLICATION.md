**Tagline**

A transparent, portable local web-development environment for Windows that keeps its services, tools, projects, and configuration inside one folder.

**Description**

Portable Developer is a GPL-licensed Windows desktop application for running an isolated local development environment from a normal folder or external drive. Users explicitly choose the web, database, browser-automation, and language tooling they need. The application does not install Windows services or modify the system PATH, registry, or firewall, and its public build and dependency provenance are designed to be auditable.

**Reputation**

Portable Developer is a newly released independent project, so it does not yet claim broad adoption, media coverage, or established download statistics. Its current trust evidence is public and verifiable: GPL-3.0-or-later source, public Windows CI, 99 automated tests, a tag-built GitHub Release with SHA-256, pinned upstream sources and hashes, a security policy, private vulnerability reporting, explicit governance and signing roles, and a release workflow tied to public commits. ## Eligibility and configuration checklist

- [x] Public OSI-approved GPL-3.0-or-later license without dual licensing.
- [x] Public source, build scripts, dependency lock, CI, tagged binary release, and documentation.
- [x] No telemetry or background transfer to project maintainers; user-triggered network behavior is documented.
- [x] Portable removal instructions and explicit system-change boundaries.
- [x] Public Code signing policy with author/reviewer/approver roles, MFA requirement, and manual signing approval.
- [x] Product name and version metadata are declared in source and consistent for future builds.
- [x] Only project-owned `PortableDeveloper.exe` is intended for project signing; third-party binaries are excluded.
- [x] Local port inspection is documented as collision prevention, not remote scanning or vulnerability discovery.
- [ ] Independent usage/reputation evidence. The project is newly released and must not overstate this field.
- [ ] SignPath Foundation acceptance and technical project configuration.
- [ ] SignPath signing workflow with mandatory manual approval and artifact metadata restrictions.
